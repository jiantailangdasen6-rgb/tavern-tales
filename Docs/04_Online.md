# オンライン（M2）の設計

## つなぎ方
- Unity Relay のルームコード（前作「ラビリンス・サバイバー」と同じ Unity Cloud プロジェクト `f2ea130d-…` を流用。Relay は有効）。
  Windows 同士なので DTLS（UDP の暗号化）でつなぐ。匿名サインインは `-profile` ごとに分ける（同じ PC で複数起動して試せる）。
- Netcode for GameObjects は「名前付きメッセージ」だけを使う（NetworkObject は使わない）。ターン制で文章中心なので、
  宣言と状態の送り合いで足りる。大きい状態は `ReliableFragmentedSequenced` で送る。
- 招待リンク（https の中継ページ → ゲームを起動）は後で足す。まずはコードの手入力。

## 役割
- **ホスト**: `TavernGame`（AI・ルール・サイコロ・保存）を持つ。自分のキャラクターも遊ぶ。
- **友人**: 自分のキャラクターを作って部屋に入る。宣言を送り、ホストから届く「状態」を表示する。
  状態は `SaveData` と同じ形（AI の履歴は送らない、ログは新しい分だけ）。友人の PC では、その状態から
  読むだけの `TavernGame` を組み立て、ホストと同じテーブル画面で描く。

## メッセージ
| 向き | 名前 | 中身 |
|---|---|---|
| 友人→ホスト | `hello` | 名前と、作ったキャラクター（`CharacterSave`） |
| ホスト→全員 | `lobby` | 集まった顔ぶれ、始まったか |
| 友人→ホスト | `declare` | 自分のキャラクターの宣言（`Declaration`） |
| ホスト→全員 | `turn` | 状態（`SaveData` から履歴を除いたもの）＋ この手番の新しいログ ＋ 誰が宣言済みか |
| ホスト→持ち主 | `ask_reroll` / 持ち主→ホスト `reroll` | 運命のコインで振り直すか |
| ホスト→持ち主 | `ask_growth` / 持ち主→ホスト `growth` | 幕の終わりの成長 |
| 友人→ホスト | `order` | 語り部への注文 |

## 手番の進み方
- 各自が自分のキャラクターの行動を決めて「宣言する」。ホストは、動ける全員の宣言がそろったら自動で手番を進める。
- 待っている間、画面の左に「宣言済み / 考え中」が出る。

## 切断と再開
- 友人が落ちたら、同じコードで入り直す（名前で自分のキャラクターに戻る）。
- ホストが落ちたら、ホストが「続きから」で部屋を開き直し、新しいコードで全員が戻る（保存はホストの PC）。

## 確かめ方
- 同じ PC でホスト 1 + 友人 2 を起動し、ボットで数手番遊ばせて、全員の画面が同じ状態になるかをスクリーンショットで見る
  （`Tools/OnlineTest.ps1`）。AI は `-demo`（無料枠を使わない）。
